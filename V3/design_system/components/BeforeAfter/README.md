# BeforeAfter

Shows a change as what it was and what it becomes. Use it wherever a source, a procedure or a draft changes: the user must always see both sides.

- **Before**: `errorContainer`, struck through. **After**: `primaryContainer`.
- Name the revisions in the column headings ("Before · Rev C", "After · Rev D draft").
- A NOTE line in `primary` under After records the configuration the old text still applies to.
- **Because** gives the reason and its source.

The strike-through and the headings carry the meaning; the colours only support them.
